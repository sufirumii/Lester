Six things you can't get from a chat UI

Runtimes, chat apps and RAG tools each cover one slice. Lester is the control plane that covers the rest.

Lester Proof

A built-in “data stayed local” ledger. Every request records which model handled it, where it ran, and whether any byte left the machine. Exports a signed, tamper-evident PDF and JSON report an auditor can read.

Lester Fit

Upload 20–200 of your own real prompts. Lester runs them against candidate local models, measures quality, speed and tokens — then reports the cost saved per month if the workload moves local.

Policy router

Per-workspace rules decide whether a request stays local, may fall back to a cloud API, or is blocked. PII and secret detection redacts before anything leaves. Cloud fallback is off by default.

Hardware-aware setup

First run scans CPU, RAM, GPU and disk, then recommends quantized models that actually fit. No manual tuning.

Always-on durability

Write-ahead logging, atomic writes, scheduled checksummed backups, crash recovery, optional encryption at rest, one-click export and restore.

One command, no external services

Single installer or one docker compose up. No external databases, no cloud accounts. Runtime is fully offline; installing needs the package registry (and Docker images) — DEPLOY.md lists every network touch honestly.

From zip to auditable in four steps

Everything below happens on your machine. The only download is the model itself.

  1. Install

    docker compose up -d or bash install.sh (Windows: install.ps1). Lester binds to localhost and requires authentication from the first second.

  2. Scan & pick a model

    The setup wizard detects your hardware and recommends quantized models that fit — or connect an existing Ollama / LM Studio / OpenAI-compatible runtime.

  3. Set policy per workspace

    Local-only by default. Add keyword blocks, model allow-lists and PII redaction. Try any request in the live policy tester before it ever touches a model.

  4. Prove it

    Export the signed Proof report any time. Auditors verify it offline with one command: bun run proof:verify -- report.json.

Secure by default, honest by design

  • Localhost until you say otherwise. The server binds to 127.0.0.1 by default; LAN exposure requires an explicit environment setting (LESTER_BIND) and a restart — never a Console toggle.
  • Cloud fallback needs two keys. Policy mode AND a configured provider — off by default, every byte recorded.
  • Redaction before dispatch. Luhn-validated cards, SSN, IBAN, emails, phones, API keys, private keys.
  • No prompt content in audit logs unless an admin explicitly enables it. Encrypted API keys at rest.
  • Zero telemetry. Not disabled — absent. The only outbound bytes possible are policy-approved cloud calls.

Quickstart

The full documentation set ships inside the package: README and the docs/ guides (guide, security model, proof & fit, api & architecture).

unzip lester-v1.0.2.zip && cd lester-v1.0.2
docker compose up -d          # or: bash install.sh
open http://localhost:8090    # first-run wizard: hardware scan → admin → model

# verify a proof report offline
bun run proof:verify -- lester-proof-2026-11-08.json

# run the test suite (durability · policy · redaction · chain · migrations · OpenAI-SDK e2e)
bun run test

Existing OpenAI-compatible app? Point it at Lester with one URL change:

POST http://localhost:8090/api/v1/chat/completions
Authorization: Bearer lst_…   # create in Settings → API tokens (stored hashed)
# same policy, same redaction, same Proof ledger as the Console
